### 1.2 ⚠️ 必须纠正：828 不是品种数

体检脚本的第一个真实价值：它没放过脏数据。

```
828 条记录 → 唯一名称 604 个
  重名组 206 组（内容完全相同 8 组，内容互相冲突 198 组）
```

冲突是实质性的，不是简单的重复行：

| 药材 | 冲突内容 |
|---|---|
| 续断 | 既被标为「补虚药」又被标为「活血化瘀药」（3 条记录） |
| 附子 | 两个不同的成分列表（「乌头碱、次乌头碱…」vs「附子碱、挥发油…」） |
| 酸枣仁 | 归经「心肝经」vs「肝心经」，功效表述两种 |

**处理方式**：`scripts/clean_dataset.py` 做确定性合并（类别/归经/用量取众数，功效取最长，
成分取并集），保留 `merged_from` / `source_indexes` / `conflicts` 便于溯源，
198 条冲突条目清单写入 `docs/数据去重报告.md` 供人工复核。

**对外口径必须改**：论文与答辩 PPT 中，不要把 828 当成药材品种数。建议表述为
「原始 828 条记录，去重合并后 604 味药材，另有 22 味药食同源品种由法定目录补齐，合计 626 味」。
这是一个会被现场核验的数字。

### 1.5 体质判定引擎（ADR-002 / BC3）

- **确定性**：纯函数，同一份问卷两次运行得分、主体质、兼夹、证据链完全一致（有单测）
- **计分算法**：`转化分 = [(原始分 − 条目数) / (条目数 × 4)] × 100`，阈值 ≥40「是」/ 30–39「倾向是」/ <30「否」，平和质需 ≥60 且其余 8 种 <30
- **问卷**：9 维度 × 3 题 = 27 题（完整版）/ 每维度 1 题 = 9 题（快速版，对应 UI 原型的 5–8 题形态）
- **不强行辨证**：信息不足或前两名得分接近时输出 `needs_follow_up`，由 AI 追问补充，**不会硬判**
- **可解释**：`evidence` 逐条回溯到具体题目与答案

实测输出（模拟「怕冷 + 易累」用户）：

```
主体质：阳虚质（判定为是）   兼夹：['气虚质']
标准：GB/T 46939—2025   确定性：True
九维转化分：{"平和质":50.0, "气虚质":58.3, "阳虚质":100.0}
推理依据：
  · 「你平时手脚发凉、怕冷吗？」回答：总是 → 指向阳虚质特征
```

### 1.6 药材匹配推荐（BC4）

- **规则表**：9 种体质 × 10 味 = 90 条规则（初稿，版本 `v0.1-draft`，写入每次结果便于复现）
- **100% 白名单校验**：规则表引用的药材名由 `tests/test_rule_table.py` 断言必须 ∈ 106 白名单
- **主诉加成 + 保底槽位**：用户说「失眠」时，酸枣仁必定出现（单纯按得分排序会被体质基线挤掉）
- **强制过安全层**：任何候选先经黑名单/白名单/配伍/人群过滤后才输出，`rejected` 列表说明被拦原因

### 1.7 问诊闭环（BC2）

```
POST /api/v1/consultation/start
   ① 输入侧安全闸（急症 → 40301 终止并入库留痕）
   ② 确定性判定 → needs_follow_up?
        是 → LLM 生成追问（≤3 问，≤2 轮；LLM 不可用时降级为模板）
        否 → ③ 药材匹配 → ④ 输出侧安全闸 → ⑤ 落库
POST /api/v1/consultation/{id}/answer   追加回答 → 重新判定 → 最多 2 轮后收敛
GET  /api/v1/consultation/{id}/stream   SSE：meta / delta / done / error
```

每轮回答同步把问卷快照写入 `consultations.questionnaire`，
按 U11 的回答，缓存丢失也能恢复（本阶段用 DB 承担 checkpointer 职责，Redis 仍为可选）。
