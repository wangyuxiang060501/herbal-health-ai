# 部署手册（6.3）

> 目标：把系统部署到一台云服务器，通过 `https://<域名>` 访问。
> 本文写的是**可执行的操作步骤**；其中「域名备案」与「实际购买服务器」需由本人完成，
> 本文档给出流程与检查清单，但不替代实际执行。

---

## 一、组件拓扑

```
                          ┌──────────────────────────┐
   浏览器 ── HTTPS 443 ──▶│  frontend (nginx:alpine) │
                          │   · 静态文件 /assets      │
                          │   · SPA 回落 index.html   │
                          │   · /api ──▶ backend      │  ← 反向代理
                          └────────────┬─────────────┘
                                       │ 内网
                          ┌────────────▼─────────────┐
                          │  backend (uvicorn:8000)   │
                          │   · FastAPI + LangGraph   │
                          │   · SQLite(WAL) + Chroma  │
                          └──────────────────────────┘
                          ┌──────────────────────────┐
                          │  certbot（12h 检查续期）   │
                          └──────────────────────────┘
```

设计要点：

- **backend 不暴露宿主机端口**，只能由 nginx 通过容器内网访问 —— 少一个攻击面。
- **Nginx 对 `/api/` 关闭 `proxy_buffering`**，否则 SSE 流式输出会被攒成一坨，
  前端的打字机效果变成最后一次性弹出。这是部署阶段最容易忽略的一处配置。
- **运行时数据挂卷**（SQLite / Checkpointer / Chroma 索引），容器重建不丢数据。

## 二、前置条件（人工完成，6.3.4）

| # | 事项 | 说明 | 状态 |
| --- | --- | --- | --- |
| 1 | 购买云服务器 | 2 核 4G 起（本地跑 qwen3:8b 需 8G+；若只用云端 LLM，2C4G 足够） | ☐ |
| 2 | **域名 ICP 备案** | 中国大陆服务器对外提供服务的法定前提，通常需 10–20 个工作日 | ☐ |
| 3 | 公安备案 | 网站上线后 30 日内，在「全国互联网安全管理服务平台」提交 | ☐ |
| 4 | 域名 A 记录指向服务器公网 IP | `your.domain.com → x.x.x.x` | ☐ |
| 5 | 安全组放行 80 / 443 | 8000 端口**不要**对公网开放 | ☐ |

> ⚠️ **顺序很重要**：先备案，再解析，最后部署。未备案的域名解析到大陆服务器会被阻断，
> 表现为「Nginx 起来了但外网访问不了」，很容易误判成配置错误。

## 三、部署步骤（6.3.5）

```bash
# 1) 服务器上准备代码
git clone <your-repo> herbal && cd herbal

# 2) 环境变量
cp .env.example .env
#   至少确认这几项：
#     LLM_PROVIDER / LLM_MODEL / 对应 API_KEY
#     APP_ENV=production   DEBUG=false
#     APP_SECRET_KEY=改成随机值
#     MONTHLY_BUDGET_CNY=按需设定

# 3) 渲染 Nginx 配置里的域名
export DOMAIN=your.domain.com
sed -i "s/\${DOMAIN}/$DOMAIN/g" deploy/nginx.conf

# 4) 构建并启动
docker compose -f docker-compose.prod.yml up -d --build

# 5) 自检（此时还没有证书，先用 HTTP）
curl -I http://$DOMAIN                      # → 301 跳 HTTPS（还没证书会失败，属正常）
docker compose -f docker-compose.prod.yml logs -f backend
curl http://127.0.0.1/api/v1/meta/dataset   # 容器内地址，验证后端

# 6) 申请 HTTPS 证书（6.3.3）
chmod +x deploy/init-ssl.sh
./deploy/init-ssl.sh $DOMAIN your@email.com

# 7) 验证
curl -I https://$DOMAIN
docker exec herb-certbot certbot certificates
```

## 四、上线后检查清单

- [ ] `https://<域名>` 首页可打开，无混合内容告警
- [ ] 体质测试 → AI 追问 → 结果页 → 药膳页 全流程跑通（含手机浏览器）
- [ ] SSE 打字机效果是**逐字**出现（若不逐字，检查 `proxy_buffering off` 是否生效）
- [ ] `https://<域名>/api/v1/health` 返回正常
- [ ] 急症输入（如"胸痛"）仍被拦截 —— 安全层不能因部署变化失效
- [ ] 推荐药材全部 ∈ 106 药食同源（`/api/v1/safety/probe-herbs` 自查）
- [ ] `docker exec herb-certbot certbot certificates` 显示证书有效期
- [ ] 服务器时间与本地一致（时间偏差会导致 HTTPS 校验失败）

## 五、运维要点

| 场景 | 操作 |
| --- | --- |
| 查看后端日志 | `docker compose -f docker-compose.prod.yml logs -f backend` |
| 重启后端 | `docker compose -f docker-compose.prod.yml restart backend` |
| 更新代码 | `git pull && docker compose -f docker-compose.prod.yml up -d --build` |
| 备份数据 | `docker run --rm -v herb-backend-data:/data -v $PWD:/backup alpine tar czf /backup/var-$(date +%F).tgz /data` |
| 证书续期 | 自动（certbot 容器每 12h 检查）；手动：`docker exec herb-certbot certbot renew` |
| 回滚 | `git checkout <上一版 commit> && docker compose -f docker-compose.prod.yml up -d --build` |
